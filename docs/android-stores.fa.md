# انتشار اپ اندروید در کافه‌بازار و مایکت

تصمیم مالک (۲۰۲۶/۱۱/۰۸، دستور ۱۲۰ در `AGENTS.md`): برای هر فروشگاه یک نسخهٔ جدا با پرداخت درون‌برنامه‌ای همان
فروشگاه ساخته می‌شود، خرید روی سرور با API خود فروشگاه بررسی می‌شود، و وب/PWA و APK مستقیم (GitHub Releases) همچنان
با زیبال پرداخت می‌کنند. هر دو فروشگاه برای اشتراک و امکانات دیجیتال پرداخت درون‌برنامه‌ای خودشان را لازم می‌دانند و
هدایت کاربر به درگاه بیرونی را ممنوع کرده‌اند؛ مایکت قیمت یکسان در همهٔ بازارها را هم لازم می‌داند.

## چطور کار می‌کند

- اپ اندروید سه flavor دارد: `direct` (همان APK گیت‌هاب، با زیبال)، `bazaar` و `myket`. نسخه‌های فروشگاهی به انتهای
  user agent عبارت `PoshtetgarmStore/bazaar` یا `PoshtetgarmStore/myket` را اضافه می‌کنند و صفحهٔ `/app/billing` در
  آن‌ها هیچ اشاره‌ای به زیبال یا درگاه ندارد؛ پوسته هم باز کردن دامنهٔ `zibal.ir` را در این نسخه‌ها می‌بندد.
- هر پلن یک محصول **مصرفی** (consumable) در فروشگاه است، نه اشتراک: پلن‌های ما تمدید خودکار ندارند (دستور ۱۱۶) و
  اشتراک بازار به‌طور پیش‌فرض خودکار تمدید می‌شود. شناسهٔ محصول (SKU) همان کد پلن در `/admin/billing` است که `-`
  در آن به `_` تبدیل شده (مثلاً `three-months` ← `three_months`).
- خرید: اپ اول از سرور می‌پرسد (`POST /api/billing/store/intent`؛ در سه روز آخر اشتراک یا بدون اشتراک مجاز است، دستور
  ۱۱۸)، بعد برگهٔ خرید فروشگاه را با payload حساب کاربر باز می‌کند، و توکن خرید را به `POST /api/billing/store/verify`
  می‌فرستد. سرور توکن را با API فروشگاه برای همان SKU بررسی می‌کند، payload باید همان حساب باشد، و دسترسی از همان
  مسیر قفل‌دار زیبال (`activate`) یک بار اضافه می‌شود. هر توکن فقط یک بار فعال می‌کند؛ تکرار از همان حساب «پرداخت‌شده»
  جواب می‌گیرد و از حساب دیگر رد می‌شود. اگر فروشگاه در دسترس نباشد چیزی ثبت نمی‌شود و خرید مصرف‌نشده می‌ماند؛ دفعهٔ
  بعد که کاربر صفحهٔ اشتراک را باز کند، اپ آن را دوباره می‌فرستد. خرید فقط پس از تأیید سرور مصرف (consume) می‌شود.
- سفارش‌های فروشگاهی در `/admin/billing` با برچسب «کافه‌بازار» یا «مایکت» دیده می‌شوند. مبلغ ثبت‌شده قیمت پلن است؛
  کارمزد فروشگاه جدا از آن کم می‌شود.

## کارهایی که شما باید انجام دهید

ترتیب پیشنهادی: ۱ ← ۲ و ۳ ← ۴ ← ۵. هیچ کلید یا رمزی را در گیت، چت یا تیکت نگذارید.

### ۱. کلید امضای انتشار (یک بار برای همیشه)

فروشگاه‌ها به‌روزرسانی را فقط با همان کلید امضای نسخهٔ اول می‌پذیرند؛ اگر این کلید گم شود دیگر نمی‌توانید اپ را در
همان صفحه به‌روز کنید. نسخهٔ `direct` همچنان با کلید debug قبلی امضا می‌شود تا نصب‌های فعلی به‌روز شوند.

```bash
keytool -genkeypair -v -keystore poshtetgarm-release.jks -alias poshtetgarm -keyalg RSA -keysize 4096 -validity 10000
```

```bash
base64 -i poshtetgarm-release.jks | pbcopy
```

در GitHub ← Settings ← Secrets and variables ← Actions، این چهار **Secret** را بسازید: `ANDROID_KEYSTORE_BASE64`
(خروجی دستور بالا)، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS` (`poshtetgarm`)، `ANDROID_KEY_PASSWORD`. از فایل
`.jks` و رمزها نسخهٔ پشتیبان امن بیرون از این لپ‌تاپ نگه دارید.

### ۲. کافه‌بازار

1. در [پیشخان توسعه‌دهندگان بازار](https://pishkhan.cafebazaar.ir) حساب توسعه‌دهنده بسازید و احراز هویت را کامل کنید.
2. برنامهٔ جدید با نام بستهٔ `ir.poshtetgarm.poshtetgarm_hybrid` بسازید.
3. در بخش پرداخت درون‌برنامه‌ای، **کلید عمومی RSA** را کپی کنید و در GitHub به‌عنوان **Variable** (نه Secret) با نام
   `BAZAAR_RSA_PUBLIC_KEY` بگذارید. این کلید عمومی است و داخل APK قرار می‌گیرد.
4. برای هر پلن فعال در `/admin/billing` یک محصول درون‌برنامه‌ای **مصرفی** بسازید. شناسه‌ها برای پلن‌های فعلی:
   `monthly` (۲۴۹٬۰۰۰ تومان)، `quarterly` (۶۴۹٬۰۰۰ تومان) و `yearly` (۱٬۹۹۰٬۰۰۰ تومان)؛ قیمت باید دقیقاً همان قیمت
   پلن باشد. محصول «اشتراک» نسازید.
5. در بخش API توسعه‌دهندگان، کلید API پیشخان را بسازید؛ این کلید سرّی است و فقط روی سرور با نام `BAZAAR_API_SECRET`
   قرار می‌گیرد (مرحلهٔ ۴). اگر پنل فقط کلاینت OAuth می‌دهد، به‌جای آن `BAZAAR_CLIENT_ID`، `BAZAAR_CLIENT_SECRET` و
   `BAZAAR_REFRESH_TOKEN` لازم است؛ برای گرفتن refresh token از Claude کمک بخواهید.

### ۳. مایکت

1. در [پنل توسعه‌دهندگان مایکت](https://developer.myket.ir) حساب بسازید و احراز هویت کنید.
2. برنامه با همان نام بستهٔ `ir.poshtetgarm.poshtetgarm_hybrid` بسازید.
3. کلید عمومی RSA پرداخت درون‌برنامه‌ای را در GitHub به‌عنوان **Variable** با نام `MYKET_RSA_PUBLIC_KEY` بگذارید.
4. همان محصولات مصرفی با همان شناسه‌ها و همان قیمت‌ها را بسازید (قانون مایکت: قیمت یکسان در همهٔ بازارها و وب).
5. توکن دسترسی API تأیید خرید (server-to-server) را بگیرید؛ سرّی است و فقط روی سرور با نام `MYKET_ACCESS_TOKEN`
   قرار می‌گیرد.

### ۴. کلیدهای سرور

در `/opt/all-in-one/shared/.env` روی سرور (نمونه در `deploy/.env.example`) این‌ها را بگذارید و بعد یک انتشار
(push به master یا اجرای دوبارهٔ Deploy) انجام دهید تا api آن‌ها را بخواند: `BAZAAR_API_SECRET` (یا سه مقدار OAuth)
و `MYKET_ACCESS_TOKEN`. اگر می‌خواهید Claude این کار را با `ssh flashcard` انجام دهد، مثل دستورهای ۸۱ و ۱۱۵ صریحاً
اجازه بدهید؛ کلیدها هیچ‌وقت چاپ یا در گیت ذخیره نمی‌شوند.

### ۵. ساخت، بارگذاری و آزمون

1. در GitHub ← Actions ← «Android APK» ← Run workflow (یا هر push در `native/poshtetgarm`). سه artifact ساخته می‌شود:
   `Poshtetgarm-Android-direct-…` (APKهای جدا برای هر معماری)، `Poshtetgarm-Android-bazaar-…` و
   `Poshtetgarm-Android-myket-…` (هر کدام یک APK کامل). APKهای فروشگاهی را در GitHub Releases نگذارید.
2. هر APK را در پنل فروشگاه خودش بارگذاری کنید (اول در کانال آزمایشی/بتا اگر فروشگاه دارد).
3. با یک گوشی که اپ همان فروشگاه رویش نصب و وارد شده، از صفحهٔ «اشتراک» یک پلن بخرید. اگر فروشگاه خرید آزمایشی
   دارد از آن استفاده کنید؛ وگرنه ارزان‌ترین پلن را واقعی بخرید و در صورت نیاز از پنل فروشگاه بازپرداخت کنید.
4. بررسی: صفحهٔ «اشتراک» باید «پرداخت تأیید شد» و تاریخ پایان جدید را نشان دهد، و در `/admin/billing` سفارش با برچسب
   فروشگاه و وضعیت «پرداخت‌شده» دیده شود. نتیجه را به Claude بگویید تا در رودمپ ثبت شود.

### نکته‌ها

- با تغییر قیمت یک پلن در `/admin/billing`، قیمت همان محصول را در هر دو پنل هم تغییر دهید.
- پلن تازه = محصول تازه با شناسهٔ متناظر در هر دو فروشگاه؛ تا محصول ساخته نشده، دکمهٔ خرید آن پلن در نسخهٔ فروشگاهی
  غیرفعال است و «این پلن هنوز در فروشگاه عرضه نشده است» نشان داده می‌شود.
- بازپرداخت فروشگاهی در پنل همان فروشگاه انجام می‌شود؛ بعد آن را مثل بقیه در `/admin/billing` ثبت کنید تا دسترسی کم شود.
